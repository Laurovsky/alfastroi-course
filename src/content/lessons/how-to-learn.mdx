## Как устроен курс

Курс идёт **от простого к сложному**. Сначала функции, которые можно понять за минуту и проверить одним тестом. Затем слои, которые эти функции собирают. В конце — архитектура целиком.

В каждом уроке есть четыре вида блоков:

1. **Настоящий код** — фрагменты файлов Альфастрой с путём в заголовке. Откройте тот же файл в своём редакторе и читайте рядом.
2. **«Проверь себя»** — вопрос с объяснением. Ответ сохраняется, его можно поменять.
3. **Упражнение** — вы пишете JavaScript, тесты запускаются в браузере. Красный — тест падает, зелёный — проходит. Черновик сохраняется автоматически.
4. **Интерактив** — песочницы: машина состояний, гонка двух пользователей, линтер FSD.

Прогресс хранится только в вашем браузере (`localStorage`), сервера у курса нет.

<Doka from="js/local-storage" section="Кратко">

Это объект, хранящийся в `window`, который позволяет долговременно сохранять данные в браузере. Работает как хранилище данных в формате ключ-значение […]

Значения хранятся в виде строк. […]

Не имеет ограничений по времени хранения, может быть очищен пользователем вручную или браузером при переполнении автоматически (браузеры на основе движка WebKit, например Safari, очищают `localStorage`, если к нему не обращались в течение 7 дней).

Максимальный объём данных ограничен размером 5MB.

</Doka>

Практический вывод: если вы проходите курс в Safari и неделю его не открывали, прогресс может обнулиться. А в приватном режиме некоторых браузеров запись в `localStorage` вообще выбрасывает исключение — поэтому курс сохраняет через обёртку `safeStorage`, которая в таком случае просто держит прогресс в памяти вкладки. Тот же приём («localStorage может отказать») использует и Альфастрой: при зависании Supabase сессия читается из `localStorage` в `try/catch`.

### Как упражнения проверяются в браузере

Ваш код выполняется не на сервере, а прямо во вкладке — в отдельном потоке:

<Doka from="js/web-workers" section="Что такое Web worker?">

Web worker — это API, которое позволяет выполнять код вне основного потока. Благодаря этому долгие или сложные вычисления, которые выполняются на воркерах, не блокируют пользовательский интерфейс (UI).

[…] У скрипта будет свой собственный контекст, отличный от контекста окна `window`. […] У него нет доступа к объекту документа `document` и `DOM API`.

</Doka>

Зачем это курсу? Если в решении случайно окажется `while (true) {}`, в основном потоке вкладка зависла бы намертво. В воркере зависает только воркер: курс ждёт 6 секунд, вызывает `worker.terminate()` и показывает сообщение о бесконечном цикле. А то, что у воркера нет доступа к `document`, — бонус: код упражнения не может ничего сломать на странице.

## Как запустить Альфастрой у себя

Нужны Node.js 24 и npm. В корне репозитория:

```bash
npm ci                      # зависимости всех workspace сразу
npm test -w server          # unit-тесты сервера (Vitest)
npm test -w client          # unit-тесты клиента
npm run dev -w client       # клиент на http://localhost:5173
npm run dev -w server       # API на http://localhost:3000
```

Для работы с данными нужны переменные окружения Supabase (`SUPABASE_URL`, ключи). Unit-тесты без них работают — именно поэтому бизнес-логика вынесена в чистые функции.

<Callout kind="tip" title="Как читать незнакомый код">
Начинайте с теста рядом с файлом (`*.test.ts`): он показывает, **что** функция должна делать, на примерах. Потом читайте JSDoc над функцией: в проекте принято описывать эффекты, порядок асинхронных шагов и смысл `null`. И только потом — реализацию.
</Callout>
