## Задание: комментарий к позиции анализа

> Инженер хочет оставить комментарий к строке анализа («уточнить объём у заказчика»). Комментарий видят все, у кого есть доступ к анализу. Править может только автор, пока анализ не согласован.

Пройдите по слоям сверху вниз по базе и снизу вверх по клиенту. Для каждого шага ниже — вопрос, на который нужно ответить, и правило, которое легко забыть.

## 1. База данных

- Где хранить? Поле `work_items.comment` или отдельная таблица `work_item_comments`? (Подумайте: один комментарий или история? Нужен ли автор?)
- Нужен ли `version`? Таблица «горячая» — правят несколько человек? (§2)
- Пишем ли audit? Правило §3 перечисляет таблицы, для которых аудит обязателен — входит ли `work_items`?
- Если запись многошаговая — RPC-функция с `REVOKE … FROM PUBLIC, authenticated, anon` и `GRANT … TO service_role` (§10).
- RLS-политика на чтение через `has_access_to_work_item(...)`.
- Обновить `server/test/db/baseline.sql` и написать `*.dbtest.ts`: права, конфликт версии, аудит.

## 2. Сервер

- Модуль: дописать в `modules/analyses` или новый `modules/comments`? (§11: >300 строк в service.ts или оркестрация нескольких модулей → `useCases/`.)
- `validators.ts`: Zod-схема с ограничением длины.
- `routes.ts`: `authMiddleware` → `requireRole(...)` → для POST `requireIdempotency(...)` (§9).
- `service.ts` без `req`/`res`; ошибки — классами (`ConflictError`, `ForbiddenError`).
- Права «только автор и только до согласования» — где проверяются? (Подсказка: сервер — единственный authority, §5; не забудьте второй рубеж в SQL.)
- Unit-тесты на чистую логику прав — первыми (TDD).

## 3. Общие типы

- DTO комментария — в `packages/types`, чтобы клиент и сервер говорили на одном контракте.

## 4. Клиент (FSD)

- `entities/work-item` — тип и, возможно, чтение.
- `features/comment-work-item/{api,model,ui}` — действие «оставить комментарий»: `index.ts` с публичным API.
- Виджет `analysis-editor` подключает фичу; фича не импортирует соседние фичи.
- Серверные данные — в сторе, открыта ли форма — `useState`.
- Ошибки — `translateError` + `role="alert"`; 409 → `ConflictDialog`.
- Кнопки — Gravity UI `<Button>`; `type="submit"` явно, если форма.
- Если используется `window.confirm` — паттерн `isMutatingRef`.
- `npm run lint:architecture` — 0 нарушений.

## 5. Доставка

- Все проверки CI локально: `typecheck`, `test`, `lint`, `lint:architecture`, `build`.
- Миграция и бэкенд — в каком порядке деплоить? Совместима ли миграция со старым кодом?
- После деплоя — проверить права функции через `has_function_privilege`.
